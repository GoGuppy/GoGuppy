Create your break glass accounts first and exclude them from every policy, including the Microsoft managed ones. A tenant with no exclusion and a bad CA policy is a support call to Microsoft.
Needs Entra ID P1, included in Business Premium and M365 E3.
Already Handled
Microsoft creates these itself in report only and enables them after 30 days. Check the portal before you write anything. You can toggle them and add exclusions, but not rename, delete or reconfigure them.

The Gaps
Apply in this order. Each one assumes the ones above it.
✅Require Compliant DeviceEdit First The one that turns Intune from a config tool into an access gate. Useless until compliance policies are assigned and devices actually report compliant, so deploy those first. 🔑Phishing Resistant MFA for Admins All cloud apps, not just admin portals. Targets directory roles, so a new Global Admin is covered the moment the role is assigned. Have the keys or passkeys enrolled before you turn it on. 📝Secure Security Info Registration Requires MFA or a trusted location to register authentication methods. Without it a stolen password is enough to enroll an attacker's own MFA. The most skipped policy on every baseline list. 👻Block Unknown Platforms Anything that is not Windows, macOS, iOS, Android or Linux is a script or a problem. Cheap to run, cuts a lot of noise out of the sign-in logs.
💥Break Glass Setup Coming. Two accounts, the exclusions, and the alert for when one signs in.
Notes
Exclusions are per policy, not global. Adding break glass to one policy protects you from that policy only.
Report only still writes to the sign-in logs, so you get the full blast radius before anyone is blocked.
Do not enable require compliant device while people are mid enrollment. Stagger it behind the rest.
